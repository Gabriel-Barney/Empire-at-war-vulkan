## 2. How the engine uses effects

- **Effect metadata** lives in parameters named `_ALAMO_*`: `_ALAMO_RENDER_PHASE` (which render phase draws it), `_ALAMO_VERTEX_PROC` (Mesh / RSkin / Grass / ShadowVolume / RSkinShadowVolume), `_ALAMO_VERTEX_TYPE` (the vertex declaration, e.g. `alD3dVertNU2U3U3`), `_ALAMO_TANGENT_SPACE`, `_ALAMO_SHADOW_VOLUME`, `_ALAMO_Z_SORT` etc.
- Render phases declared (FoC): Transparent 28, (none: engine/post) 25, Opaque 16, Shadow 3, TerrainMesh 3, TerrainWater 3, Heat 2, Occluded 2.
- **Phase effects** (`ENGINE\Phase*.fxo`) have no shaders: pass 0 sets the baseline device state at the start of a render phase, pass 1 restores it. Material effects only set the states they change, so the effective pipeline state of a draw = phase baseline + material pass states (see PORTING.md, PSO keys).
- **LOD / fallback ladder.** Techniques carry an annotation `string LOD` with values `DX9` (ps_2_0), `DX8ATI` (ps_1_4), `DX8` (ps_1_1..1_3), `FIXEDFUNCTION` (no shaders, texture-stage states) and `FF` (AlamoEngine.fxo). Techniques appear best-first. A leading technique named `max_viewport` (no LOD annotation) is the 3ds Max viewport preview and is not used by the game. Ladders seen (FoC, incl. max_viewport=None): FIXEDFUNCTION x25; None/DX8/FIXEDFUNCTION x15; DX8/FIXEDFUNCTION x12; DX8 x4; DX9/DX8ATI/DX8/FIXEDFUNCTION x4; DX9/DX8/FIXEDFUNCTION x4; DX9 x3; None/DX9/DX8/FIXEDFUNCTION x3.
- The highest shader models used anywhere are **vs_2_0 / ps_2_0**; most vertex shaders are vs_1_1.
- **Dynamic state expressions (FXLC).** Many passes compute states on the CPU from parameters, e.g. `AlphaBlendEnable = (m_lightScale.w < 1)` (fade-out makes opaque materials alpha-blended), `TextureFactor = Colorization`, `MaterialDiffuse = m_lightScale * Diffuse`, and `Texture0` transforms built from `m_FOWTexU/V` x `m_viewInv` for fog-of-war projection.
- **Preshaders.** Some vertex shaders carry a D3DX preshader (CPU code run on every CommitChanges) that computes extra constants (e.g. Grass: wind phase from `m_time`, `BendScale`; SPH lighting rotated into object space). The lifted `.hlsl` files show these as `cpu:` lines.

**Skinning palette:** `m_skinMatrixArray : SKINMATRIXARRAY`, `float3x4[24]` = 24 bones x 3 float4 registers = c0..c71 (rigid skinning, `_ALAMO_BONES_PER_VERTEX = 1`, vertex types `alD3dVertRSkin*`). The vertex shader reads the bone index from **NORMAL.w** (`v1.w`; the engine packs the ALO bone index there when it builds the GPU vertex buffer), truncates it (an `expp`.y frac trick), multiplies by 3, `mov a0.x`, then `dp4`/`dp3` position and normal against `c[a0.x+0..2]`. Used by 11 effects: RSKINADDITIVE, RSKINADDITIVEVCOLOR, RSKINALPHA, RSKINALPHAGLOSS, RSKINBUMPCOLORIZE, RSKINBUMPREFLECTCOLORIZE, RSKINGLOSS, RSKINGLOSSCOLORIZE, RSKINHEAT, RSKINOCCLUDEDUNIT, RSKINSHADOWVOLUME.

**Lighting model:** one directional light (`DIR_LIGHT_*_0`, world and object space), a global ambient, and two 3-element `float4x4` spherical-harmonic matrices `SPH_LIGHT_ALL` / `SPH_LIGHT_FILL` (irradiance from all lights / fill lights, evaluated per vertex), modulated by `LIGHT_SCALE` (whose .w is also the fade alpha).

## 4. Usage by ALO materials

Three corpora. **FoC** = FoC `models.meg` + Patch/Patch2 (own parser, has the per-mesh hidden flag and triangle counts). **EaW** = EaW `models.meg` (assets-stream export `eaw_alo_materials.json`, no hidden flag / vertex data) + EaW patch/patch2. **Combined** = what FoC actually loads if it mounts EaW `GameData` underneath its own `Data` (the FoC exe contains the string `..\GameData\`; mount order still to be confirmed by RE): FoC models shadow EaW models of the same name.

| corpus | ALOs with meshes | ALOs without meshes (particles / skeleton-only) |
|---|---:|---:|
| foc | 462 | 222 |
| eaw | 971 | 412 |
| combined | 1333 | 634 |

A *submesh* is one material = one draw call per model instance. *Drawn* excludes submeshes with the hidden flag (FoC) and, where the flag is unknown (EaW), the never-drawn materials `alDefault.fx`, `Default.fx` and `MeshCollision.fx` (see below). Note that the FoC hidden flag also marks meshes that the game toggles at runtime (muzzle flashes, shields, damage states), so *drawn* is a lower bound for MeshAdditive/MeshShield.

### 4.2 Never-drawn materials: alDefault.fx, Default.fx, MeshCollision.fx

Counts: FoC: alDefault 931, Default 21, MeshCollision 297 submeshes; EaW: alDefault 1048, Default 0, MeshCollision 563 submeshes; Combined: alDefault 1461, Default 21, MeshCollision 737 submeshes.

- `alDefault.fx` / `Default.fx` have **no FXO anywhere** (not in shaders.meg or any patch), so the engine cannot draw them with an effect. In FoC 927 of 931 alDefault submeshes and all 21 Default submeshes carry the hidden flag; their mesh names are collision hulls (`*_COLL`), hard-point / UI proxies (`HEALTH_*`, `SELECT_*`, `BUILD_PAD*`, `SHIELD_*`, `BUTTON_*`) and attachment markers. They are **collision / proxy geometry, not drawn**. The port should load them into the collision/proxy system only and skip them in the renderer (optionally a debug wireframe).
- `MeshCollision.fx` exists (DX8 vs_1_1 + ps_1_1 solid colour `Color`, plus an FF fallback). In FoC 296 of 297 submeshes are hidden: it is the **debug visualisation of collision hulls**, drawn only in debug views. Treat as debug-only. The EaW `models.meg` export has no hidden flag, but the same exporter conventions apply.
- Other ALO shader names with no FXO: `FISSUREMESHGLOSS` (1 submesh). The original draws these with its green default effect (docs/re/SPACE_AND_OPEN.md D.3); MeshGloss is only an opt-in compat remap (`materials::compat_missing_effect_remap()`).
