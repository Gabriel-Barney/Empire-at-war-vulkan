# A2m t08 / t10 / t14: RE answers (2026-11-09)

Roadmap a2m t08: precision of `Game.Age` against `TimeSinceCorruptionChange` (Underworld saboteur desire inputs).
a2m t10: why the retail Corellia saboteur plan exits at frame 248 and why the saboteur stops at Naboo
(`A2K_T05_SABOTEUR_RUN.md`). a2m t14: what `FindTarget(TechForce, "Is_Good_Slice_Target", "Enemy", 0.1)` considers and
how it picks, plus the unexplained run 11 of `A2M_T07_REBEL_SLICE_RUN.md`.

Source: the Ghidra decompilation of the FoC x64 `StarWarsG.exe` (RVAs relative to 0x140000000), plus disassembly of
the exe where Ghidra left a range undecompiled (0x65f0c0..0x65f1b0), and the shipped Lua / XML. Behaviour is described
in prose; no decompiled code is reproduced. Tags: [H] read directly; [M] one inferred link; [L] hypothesis.

Short answers:
- **t08 [H].** Both are doubles built from the same float constant, seconds-per-frame `spf` = (float)(1/30) =
  0.033333335f (0x3D088889), but with different rounding. `Game.Age` = (double)frame × (double)spf, one double
  multiply. `TimeSinceCorruptionChange` = (double)(float)((float)(uint32)(frame − stamp) × spf), computed in float and
  then widened. Both read the AI's galactic mode frame at desire-evaluation time (T7, before the T12 frame increment)
  and are not cached. The port's `frame / 30.0` is off by one frame at threshold crossings (Age > 120 first holds at
  frame 3600 in retail, 3601 in the port).
- **t10.** [H] The plan ends through a **synchronous No_Units_Remaining (event 7)** raised inside the simulation step,
  not by the 3-frame plan pump. Because `Underworld_Saboteur_Team` is `Is_Generic_Hero = Yes`, the task force has no
  entry that counts as a real unit. So **any** removal (0x10) or owner-change (0x1a) signal that reaches the task-force
  base handler fires event 7 even while the saboteur is still in the task force, and `Default_No_Units_Remaining`
  calls `ScriptExit`. Plan end then runs `Release_Forces(1.0)`, which gives the FADD on the same frame. [L] Which object
  sent the signal at frame 248 is not identified. [H/M] The stop planet is the end of the hop in progress: Move_To
  issues one hop at a time, destroying the block does not cancel the fleet's move, and the free store refuses to move
  a unit in transit. So the fleet finishes Shola → Naboo and waits there for the next plan.
- **t14 [H].** The candidates are every planet in the perception target list (one per planet, GOM order) that passes
  `Applies(Enemy)`. `Applies(Enemy)` requires the planet to be revealed, and the planet's `TargetPlayerID` to be neither
  the Rebel, nor a neutral faction, nor an ally. With p = 0.1, k = 1/p − 1 = 9.0f. The highest-scoring candidate (on a
  tie, the first in list order) is picked with probability 0.1. The others share 0.9 in proportion to their scores.
  There is one synced `Get_Float(0, total)` draw when at least two candidates have a positive score. Every Empire or
  Underworld planet scores 1.0 for `Is_Good_Slice_Target`. **Open [L]:** why retail never picked Corellia, Kashyyyk or
  Shola (lead: Corellia and Shola are `Home_Location` capitals). **Open [L]:** run 11. Leads: the timed tech-cost
  modifier, the black-market gate 0x39b0b0 (Nal Hutta is a black-market planet), and the t04 question of whether
  Land_Units fires the trigger at an occupied planet.

## t08. Game.Age vs TimeSinceCorruptionChange

### t08.1 The clock constants [H]

- FrameSynchronizer at 0x140b0a320:
  - +0x00 is NOW, the global logic frame;
  - +0x20 (0x140b0a340) is FPS, int 30;
  - +0x24 (0x140b0a344) is `spf`, a float. It is 0 in the image and is written once at runtime in 0x27cf90
    (at 0x27d094) as 1.0f / (float)FPS, a single-precision divide. So spf = 0.033333335f, which is
    0.03333333507180214 as a double.
- The current game mode pointer is 0x140b15418, and the mode frame is at mode +0x10 (int32).
  - GameModeManager::Post_Tick 0x28a4c0 increments it at T12 unless the mode is paused (`MAIN_LOOP.md`).
  - The galactic AI evaluates desires at T7, so it sees the number of completed unpaused ticks.

### t08.2 Game.Age (leaf 0x6e1f20) [H]

1. The frame is read as a signed int32 from the current mode's +0x10, or 0 when there is no mode.
2. If the evaluation context has a player object (ctx +0x58 → +0x40 → +0x28), the frame comes instead from that
   player's own mode:
   - 0x5f55e0 calls 0x28a950 on the GameModeManager (0x140b153e0) with the type id at obj +0x34;
   - 0x28a950 returns the first mode in the manager's list (+0x48, count +0x50) whose type (vf +0xe0) matches.
   - In a plain galactic game this is the same galactic mode.
3. out = (double)frame × (double)spf. The int is converted exactly to double, the float is widened exactly, and there
   is a single double multiply, rounded once. Always succeeds.
4. Lifetime 0, so there is no cache: the value is computed on every evaluation.

### t08.3 TimeSinceCorruptionChange (leaf 0x65f110) [H]

1. Fails (returns false, leaving the output unset) if the evaluator's planet (+0x98) is null or the planet's
   PlanetData (planet +0xb8) is null.
2. d = (current mode frame, or 0 with no mode) − PD +0x2F0, a 32-bit integer subtraction.
3. d is zero-extended to 64 bits and converted with cvtsi2ss. So it is converted as an **unsigned** 32-bit value to
   float, rounded to nearest-even. A negative d would become a huge value; that does not happen in practice.
4. The float is multiplied by spf in float (mulss, rounded to float) and then widened exactly to double.
5. Result: `(double)(float)((float)(uint32)(F − stamp) × 0.033333335f)`.
6. It uses the global current mode (0x140b15418), not the player's mode found through 0x5f55e0. In a galactic-only
   game these are the same.

PD +0x2F0, the corruption stamp:
- the PlanetData constructor 0x4b5700 sets it to 0, so before any change it counts from frame 0 and does not return
  1e18;
- corruption Complete 0x4b7a50 writes the current mode frame to it, and it is the only writer;
- it is saved and loaded with PlanetData (micro chunk 101).

### t08.4 The other TimeSince leaves (correction) [H]

0x65f0c0 (Conversion, evaluator stamp +0xe0), 0x65f160 (Ground conflict, +0xdc) and 0x65f1b0 (Space conflict, +0xd8)
are one shape:
- stamp < 0 → 1e18, read from the f64 constant at 0x85b8c0 (999999984306749440.0, i.e. (double)1e18f);
- otherwise (double)(int32)(NOW − stamp) × (double)spf, with NOW = 0x140b0a320 (the global frame, not the mode
  frame).

This corrects `AI_GALACTIC_TOKENS.md`, which says "(NOW − stamp)/FPS": the value is multiplied by the widened float
spf, not divided by 30. Also, 1e18 is the float-rounded value 999999984306749440, not exactly 1e18.

### t08.5 Check against the retail trace [H]

The fit in `A2K_T05_SABOTEUR_RUN.md` §3 is exactly these two formulas. With stamp = 0:
- it reproduces all 21 sampled on/off values of the saboteur desire (on at 30, 60, 120, 240, 270, 480, 510, 540,
  103, 397, 1495; off at 691 and the others);
- with the two roundings, the comparison between Age and TimeSince comes out "on" on about 49.79% of frames.

### t08.6 What the port should do

- `Game.Age`: `static_cast<double>(frame) * static_cast<double>(1.0f / 30.0f)`. This replaces
  `engine/ai/src/galactic_ai_tokens.cpp:2045` (frame / kAiFps).
- `TimeSinceCorruptionChange`:
  `static_cast<double>(static_cast<float>(static_cast<float>(static_cast<uint32_t>(frame - stamp)) * (1.0f / 30.0f)))`.
  This replaces `:1532-1533`. Keep the stamp at 0 from the start of the game.
- `TimeSinceConversion` / `…GroundConflict` / `…SpaceConflict`:
  - stamp < 0 → `static_cast<double>(1.0e18f)`;
  - else `static_cast<double>(frame - stamp) * static_cast<double>(1.0f / 30.0f)`.
  - This replaces the `/ kAiFps` at `:1537-1541` and `kNever` at `:258`.
- Store spf as a `float` constant computed as 1.0f / 30.0f. Rely on `/fp:precise` with no FMA contraction (rule 3)
  so the float multiply is not fused or kept in double.
- [M] NOW (global frame) and the galactic mode frame are the same count in a galactic-only game. Keep one frame
  counter unless a mode switch (a tactical battle) is shown to make them differ.
- Sampling: evaluate at desire time with no caching.

## t10. The Corellia saboteur plan exit at 248 and the stop at Naboo

### t10.1 The retail record (from A2K_T05)

| frame | event |
|---|---|

| 120–210 | unit in fleet 551, in transit |
| 235 | PPROD true (AssembleForce done); `Move_To(Corellia)` starts |
| 240 | unit in fleet 552, in transit |
| 241 | FSAB false |
| 248 | PEXIT (by=nodebug, target changed false, blocks 2) and FADD with planet nil, unit in transit |
| 330–390 | unit at Naboo in fleet 552 |
| 397 | new plan @Naboo takes 323 |

### t10.2 Frame phase: a synchronous engine dispatch [H]

- The plan pump runs every 3 frames (Planning 0x725bc0).
- Every AI-service record in the trace is at a frame ≡ 1 (mod 3): 103, 235, 241, 250, 397, 517, 616, 691, 1495. These
  records are plan starts, PPROD / PMOVE, and free-store services.
- 248 ≡ 2 (mod 3). So the `ScriptExit` at 248 was not run by the plan pump, and not by a queued event (queued events
  drain in `PumpEvents` on a pump frame).
- It must come from a synchronous handler call: plan event dispatch 0x6006b0 with queued = 0, made during the
  simulation step by a task-force signal handler.

### t10.3 Why any removal signal ends this plan [H]

Task-force vtable (galactic) 0x8bfec0:
- vf +0xa0 Add_Force 0x6cd1a0;
- vf +0xb0 0x6d0320: Release_Forces 0x5fefd0(f), then drops the elected fleet TF +0x120 if no members are left;
- vf +0xb8 Form_Units 0x6cd5b0;
- vf +0x188 0x6d0370, remove member:
  1. unsubscribes the member's signal 0x1b;
  2. calls the base remove 0x5ff610, which:
     - unsubscribes signals 0x1a, 0x10, 0x1e, 0x1f, 0x20, 0x21, 0x2b, 0x2c, 0x29 and 0x2d;
     - removes the member;
     - erases the first TF +0x60 entry of the unit's company type;
     - calls PP release 0x6c27d0, which re-admits the unit to the free store;
     - with no members left, drops TF +0x120 and ends the task force's build tasks (0x64ad00).

Galactic task-force signal handler 0x6cf810 (listener at TF +0x28):
- **0x1b** (raised only by the retreat functions 0x2ba6c0 / 0x2ba850):
  - from the elected FleetObject → vf +0xb0(1.0), i.e. Release_Forces(1.0);
  - from a member → vf +0x188(member); then if the entry vector TF +0x60 is empty → event 7, synchronous.
- **0x10** (object removed: 0x3a8380, which sets +0x3a0 bit 2 first, and 0x29f270):
  - if the sender is a fleet (+0x336 ≠ −1) whose FleetDataPack (+0xC0) has +0x70 == 0, the removal handler is skipped.
    FDP +0x70 is a type pointer set by 0x4355e0 and read by the fleet combat-power code 0x395d10;
  - otherwise the base handler 0x5fe5d0 runs;
  - then, if the sender is the FleetObject, or the FleetObject no longer resolves → event 3 (`Fleet_Destoyed`),
    unsubscribe, and re-elect TF +0x120 from the first member's parent fleet.
- Every other signal → base handler 0x5fe5d0.

Base handler 0x5fe5d0, signals 0x10 and 0x1a (0x1a = owner changed; raised only by 0x38e5a0 and only on a real
change):
1. vf +0x188(sender). If a member was removed → event 2 (`Unit_Destroyed`), synchronous.
2. Then scan the TF +0x60 entries. **Event 7 (`No_Units_Remaining`) fires synchronously unless** at least one entry
   type has all of the following:
   - `Is_Named_Hero` (+0x13) clear;
   - `Is_Generic_Hero` (+0x14) clear;
   - `Is_Special_Weapon_In_Space` (+0x1e) clear;
   - no LOBBING_SUPERWEAPON behaviour (0x370320(type, 0x37, 1)).

`MINOR_HEROES_EXPANSION.XML` gives `Underworld_Saboteur_Team` (HeroCompany, DUMMY_GROUND_COMPANY, transport
`Underworld_Hero_Shuttle`) **`Is_Generic_Hero = Yes`**. So the saboteur plan's only entry never counts. The first
0x10 or 0x1a that reaches 0x5fe5d0 for this task force fires event 7. This happens even if that signal did not remove
the saboteur, for example a fleet object the task force listens to being removed. Then:

- `AI_PLAN_UNDERWORLD_DEPLOYSABOTEUR.LUA` does not override the handler, so `Default_No_Units_Remaining`
  (PGEVENTS) runs `ScriptExit`, which gives PEXIT.
- Plan end 0x5f6a50 destroys the plan's blocks (the trace shows 2: AssembleForce's and Move_To's), then runs
  `Release_Forces(1.0)` on each task force. Release_Forces:
  - clamps f to [0, 1];
  - releases n = (int)(count × f) members: invalid members first, then by highest AI combat power (0x370e60);
  - for each released unit, calls free-store vf +0x98 (Add_Object, which logs FADD and calls `On_Unit_Added`), then
    vf +0x188;
  - finally raises event 7 if the entries are empty or f == 1.0. That event has no listener once the script has
    exited.
- This gives PEXIT and FADD on frame 248, with the unit still in transit (planet nil).

### t10.4 What was ruled out [H]

- **Event 5 (`Original_Target_Owner_Changed`):** Corellia stays EMPIRE in the 240 and 270 samples, and 0x1a fires only
  on a real owner change.
- **Production failure:** no PFAIL record, and `MainForce_Production_Failed` would also have to run on a pump frame.
- **Goal-system release:** it kills the thread without a PEXIT from the script.
- **MovementBlockStatus handler** 0x6af640 (secondary vtable 0x8bdbf0):
  - it only sets flags and dispatches events 13 (`Reached_System_On_Path`), 0 and 1 (space conflict begin / end);
  - on 0x10 / 0x1b it marks the block done and drops the fleet;
  - it never ends the plan.
- **A plain owner change of the saboteur:** 0x1a is raised only by 0x38e5a0.

### t10.6 Stage path (why the fleet id changes) [H]

From the BuildTask FSM 0x64aec0:
- **PATHING_DEST arrival.** If all of these hold, FleetManagement op 2 (detach) then op 5 (land):
  - BT +0xa8 == 0;
  - the unit has slot 0x337 (TRANSPORT);
  - the fleet's planet passes 0x39a2c0(planet, player, 1);
  - the planet's ground count (0x3f9530) is below DAT_140b168c8;
  - the surface is accessible (0x375220).
- **WAIT_FOR_ALL → TRANSPORTS_TO_ORBIT.** If the unit's parent is a planet: op 4 (launch), then op 0 (form a new
  fleet).
- **READY_TO_MERGE.**
  - If the unit's parent fleet is TF +0x120 → DO_TASK_FORCE_MERGE (0x10, Form_Units).
  - Otherwise → JOIN (0xd).
  - A galactic task force with TF +0x120 null waits.
- **PRODUCTION_END (6).** 0x5f9f90 (TF +0xa8 type count), then 0x647ee0 → Add_Force(unit) once (BT +0xd8). Add_Force
  sets TF +0x120 to the unit's parent fleet when that parent is a fleet.

So the 551 → 552 change is "land at the stage planet, launch into a new fleet". That launch is also where a stale
fleet subscription (candidate (a) above) could come from [L].

### t10.7 Why the saboteur stops at Naboo [H mechanism, M that the hop completes]

- Move_To's MovementBlockStatus issues **one hop at a time**: a MoveObjectToObject of the fleet to path[1] of the A*
  path from the fleet's current planet (0x6aebf0 / 0x6aedc0, `A2K_T08_RE_ANSWERS.md`).
- The block destructor 0x6aeb70 only releases references and unsubscribes. It does **not** cancel the fleet's current
  move, so the hop in progress at 248 (Shola → Naboo) completes.
- The free store's `On_Unit_Added` → `MoveUnit` → FreeStore `Move_Object` 0x68f5b0 refuses a unit in transit
  (0x68efb0 Is_Unit_In_Transit; log "Unit is already in the middle of a move."). So the FADD at 248 issues no new
  order.
- `On_Unit_Service` also skips units in transit. `UnitServiceRate` is 8 s, and the services at 241 and 481 bracket
  the stay.
- After arrival, the unit sits at Naboo until the next proposal pass (397) takes it for the Naboo plan.
- So the stop planet = the next node on the path from where the fleet was when the plan ended. Nothing chooses Naboo
  as a destination.

### t10.8 What the port should do

- **No_Units_Remaining test.** After a 0x10 / 0x1a signal, event 7 fires unless some remaining entry type is a "real"
  unit: not a named hero, not a generic hero, not a special weapon in space, and no LOBBING_SUPERWEAPON. Generic-hero
  task forces (the saboteur) therefore exit on the first such signal. Dispatch it **synchronously** in the simulation
  step (not on the plan pump), followed by plan end and `Release_Forces(1.0)` in the same frame. The port today uses a
  "lost every unit" check at `engine/ai/src/galactic_ai.cpp:1283-1302`.
- **Block destruction.** Destroying a Move_To block must leave the fleet's current hop running. The free store must
  not re-route a unit in transit.
- **Sender.** Until the probe in t10.5 is run, do not invent a sender. Keep the rule above and record the 248 exit as
  open [L].

## t14. FindTarget(TechForce, "Is_Good_Slice_Target", "Enemy", 0.1)

### t14.1 Arguments (FindTargetClass::Lua_Call 0x697a20) [H]

Takes 3 to 5 arguments: (task force, perception, application[, p[, range]]).
1. Argument 1 must be a task force (type DAT_140a441e0).
2. Argument 2 is the perception function name.
3. Argument 3 is a goal application name, looked up in DAT_140b31080. `Global` (0x10) is an error.
4. p must be in (0, 1]. k = 1.0f / (float)p − 1.0f, computed in float (divss, subss).
   - p = 0.1 gives exactly 9.0f.
   - With only 3 arguments, k = 0.
5. range (float): the range test is active only when range² > 0, so with 4 arguments it is off. When active, a
   candidate is rejected if the float 3-D distance² from the task-force position (vf +0x170) to the target (vf +0x68)
   is greater than range².

### t14.2 Candidates and the Enemy filter [H]

- **List.** The plan's player's AI target list: 0x5f6fb0(TF +0xf0) → +0x28 → +0x38, vector at vf +0x40, read in list
  order. In galactic mode this list has exactly one PlanetAITargetLocation per planet, in GOM category-3 order
  (`AI_GALACTIC.md` §"Galactic perception target list"). There are no fleet targets.
- **Applies** (target vf +0x20 with the application and the AI player, player +0x360). For a planet this is 0x665a30
  (PlanetAITargetLocationClass, vtable 0x8b4780 slot 4):
  1. false with no planet or no player;
  2. false unless Is_Planet_Revealed 0x3fa420 holds. That function takes no player argument:
     - true in multiplayer;
     - false with no PlanetData, or when the PlanetData's hidden flag +0x2E0 is set;
     - true if the galactic mode's `Planet_Auto_Reveal` (+0x340) is set (the default for non-story campaigns);
     - otherwise PD +0x2C9, the local human's reveal state;
  3. o = `TargetPlayerID`, evaluated through the target's evaluator (vf +0x28 → vf +0x8, token 0x140a43dc4; leaf
     0x65e980 = the player id of the planet's influence record from behaviour 3). The leaf is fogged (mask 1), but
     shipped `AIUsesFogOfWarGalactic` is False, so the value is live;
  4. o == the AI's own player id (+0x4c) → Friendly bit;
  5. else, if that player's faction is neutral (player +0x68 → +0x108) → Neutral bit;
  6. else, if allied (0x2823c0) → false;
  7. else → Enemy bit.
  The candidate passes when the result has a bit of the requested application.
- **Evaluation.** Bindings in order:
  - Self id;
  - if present, the second id at +0x478 and the human id (0x294a00);
  - the target (0x140a43c58).
  Then the perception is evaluated. A failed evaluation skips the candidate.
- `Is_Good_Slice_Target` = `1.0 - Variable_Target.IsFaction{Parameter_Faction = "Pirates", Parameter_Faction =
  "Neutral"}` (INFORMATIONGALACTICEQUATIONS.XML). So every Empire or Underworld planet scores exactly 1.0.

### t14.3 Selection [H]

1. best = 0.0 (double), with no best candidate.
2. For each candidate, with score s (double):
   - s ≤ best: if (float)s > 0, append (candidate, cum += (float)s);
   - s > best: the previous best is appended (if its (float) value > 0), and the candidate becomes the new best.
3. After the loop: if the list is empty or k == 0, return the best without a draw (nil if there is none).
4. Otherwise append the best with weight C / k (float; C = the last cumulative value) when C / k > 0. So P(best) = p,
   and the others share 1 − p in proportion to their scores.
5. Weighted_Random_Pick 0x698de0:
   - one synced draw, r = Get_Float(0, total) (0x532480 on LCG 0x140a13e24, float);
   - a binary search returns the first entry with cum ≥ r; r = 0 gives entry 0.
6. The result is wrapped as a game object (vf +0x30) or as an AI target (0x60e0a0).

For the slice plan with n applicable planets, all scoring 1.0:
- the first applicable planet in list order is the "best" and is chosen with P = 0.1;
- each of the other n − 1 planets gets 0.9 / (n − 1);
- there is exactly one synced draw when n ≥ 2, and none when n = 1;
- the order of entries in the cumulative list is the list order with the best moved to the end.

  the reveal state is the local human Empire's, which sees Corellia and Kashyyyk.

After the gates, the apply (§1.3) keeps entries with price ≤ credits.
