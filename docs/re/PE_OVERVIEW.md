## Lua

- **Lua 5.0.2, statically linked** (`$Lua: Lua 5.0.2 Copyright (C) 1994-2004 Tecgraf, PUC-Rio $`). Both the parser (`` `=' or `in' expected``, `unfinished string`) and the undumper (`bad code in %s`, `virtual machine mismatch in %s: size of %s is %d but read %d`, `size_t`, `Instruction`) are present, so `lua_load` accepts **both source and precompiled chunks**, auto-detected by the `\033Lua` signature.
- The undump header check compares `sizeof(size_t)`/`sizeof(Instruction)`/`sizeof(lua_Number)`; retail 32-bit bytecode (config.meg) has 4-byte `size_t` and is rejected by this x64 VM. That is why 64Patch.meg ships plain-text sources for every script.
- `LUA_PATH` default `./?.lua;./?.lc`; `?;?.lua` in `require`. Engine-side bindings: see `LUA_API.md`.

## Companion binaries

- **PerceptionFunctionG.dll** (1074176 bytes, PDB `PerceptionFunctionG.pdb`): imports only KERNEL32/USER32/WINMM; exports 45 C++ symbols (`ThePerceptionFunctionManagerClass::System_Initialize(MegaFileManagerClass*, bool)`, `Read_Equation_File`, `PerceptionFunctionClass::Build/Evaluate(PerceptionContextClass const&, double&)`, `Init_Perception_DLL(...)`). The exe passes callbacks into `Init_Perception_DLL` (token-to-value evaluator, allocator, string conversions) and the DLL parses `Data/XML/AI/PerceptualEquations/*.xml` into expression trees (AdditionOperatorNodeClass, ClampFunctionNodeClass, ... 125 RTTI classes in `rtti_perception_dll.txt`). Evaluation is a pure function of a PerceptionContext -> safe to run on worker threads if the token callbacks are made read-only.
- **tbbR.dll** (Intel TBB 2.x-era API: task_scheduler_init, concurrent_queue/vector, pipeline; 216 exports; built 2022-08-25): **not imported or LoadLibrary'd by StarWarsG.exe, the EaW exe, or PerceptionFunctionG.dll**, and no `tbb` strings exist in the exe. The engine does not use it; it is a redistributable leftover (probably for the launcher/crash tooling). The engine is effectively single-threaded: the only `CreateThread` call site (`0x786138`, via ThreadClass at `0x22e490`) is used by the loading-screen thread, network packet/NAT threads (PacketHandlerClass, NATUtilsThreadClass) and BattleLoadDialog.
- `d3d9.dll`/`dxgi.dll` in `corruption\` = DXVK v3.1.1 (log: Vulkan device AMD RX 9070 XT).
- `d3dx9_43.dll` in `corruption\` is **not Microsoft's**: it is the entry of the third-party patch proxy chain (see `PRIOR_PATCH.md`); the genuine D3DX is renamed `eaw_modifier_d3dx_original.dll`.
