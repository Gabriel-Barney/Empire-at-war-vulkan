Agents check here before planning and add a dated row here for any new decision; the roadmap (`roadmap-store/`) holds status only. Moved verbatim on 2026-11-06 from `CLAUDE.md` ("Platform and compilers") and `docs/PHASE4.md` ("Decisions", "Camera and controls", "Graphics and display", "G0 - simulation foundation"); the rule in `docs/ROADMAP_PROTOCOL.md` that out-of-scope work is recorded here first still holds.

## Platform, compilers and scope (Gabriel, 2026-10-27)
- **Windows x64 is the only supported platform.** No other platforms, no non-Windows code paths
  (Gabriel, 2026-10-29). Multiplayer is out of scope (Gabriel, 2026-10-29): no networking, lobby or MP-only work.
  Loading the original game's save files is out of scope too (Gabriel, 2026-10-29): the port uses only its own save format (N1).
  Parity with the original is checked by behaviour, not by matching its CRC / hashes bit for bit (Gabriel, 2026-10-29);
  the port's own determinism rule 3 is unchanged. RenderDoc is out of scope: captures use apitrace.
- **Two compilers: MSVC (ships) and clang (checks).**
- Every change: MSVC build + tests. Changes to sim code (everything in `engine/` except render, audio,
  video and UI): also the clang build + tests, including the CRC selfchecks. Changes to `engine/jobs` or
  other threading code: also `build_asan.cmd` (clang UBSan by default; `set ALAMO_SANITIZE=address` for ASan, which then runs with `-asan-stack=0` (heap and globals only) because stack instrumentation crashes catch handlers on this toolchain, see `docs/BUILD.md` "Sanitizer limits"; the default module list is the 11 sim modules; no TSan runtime on Windows, so races are covered by the per-worker-count CRC tests).
- Shaders are compiled by DXC (`toolchain\dxc`) to SPIR-V; the C++ compiler choice doesn't affect them.

## Branching (Gabriel, 2026-11-06)
- **One long-lived integration branch, `dev`, instead of a branch per task, task group or session.** The repository had 319 branches, nearly all created per session and merged by PR; nothing required that and `main` is not protected.
- Tasks commit and push to `dev`. Gabriel merges `dev` into `main` by PR when he chooses, after `build_gate.cmd` passes on `dev`. Never push `dev` with a failing MSVC build or test (a red `dev` blocks every agent).
- `dev` is the development branch and GitHub's default branch; `main` only moves when Gabriel releases `dev` into it (Gabriel, 2026-11-06: "dev is the main branch during development ... merged from the dev branch into the main branch when ready"). Release: `build_gate.cmd` on `dev`'s tip, then `gh pr create --base main --head dev` and merge it with a merge commit (not squash or rebase: those copy `dev`'s commits under new ids, and the next release then conflicts).
- A short branch off `dev` is allowed only for a parallel lane (git permits one branch per worktree). It lands on `dev` with `tools\land_on_dev.cmd` (no PR) and is deleted, local and remote, when the lane ends. `tools\new_worktree.cmd` branches from `origin/dev` by default and `tools\clean_worktrees.cmd` counts a branch as merged once it is in `origin/dev` (or `origin/main`).
- The desktop app starts every session on its own `claude/<name>` branch and has no setting to base it on `dev` (its `branch_prefix` setting only renames them; this session's branch started at the `origin/main` tip while `main` was the GitHub default), so docs alone cannot stop those branches. `tools\land_on_dev.cmd` makes them harmless: it refuses on `main`, detached HEAD and uncommitted tracked edits, merges `origin/dev` into the session branch (conflicts are resolved in that tree, so `dev` never holds a broken merge), pushes to `dev` as a plain fast-forward (no force; a rejected push means `dev` moved, rerun), and deletes the session branch on origin. The branch gets no PR to `main`. Run it after the builds and tests the change needs. `--create` makes `dev` from `origin/main` the first time.
- Cleaning up the existing merged `claude/*` branches is a separate step; deleting remote branches needs Gabriel's go-ahead.
- Rules for agents: `CLAUDE.md`, "Rules" / "Branches"; remotes: `docs/BUILD.md`.

## G0 — simulation foundation (Gabriel, 2026-10-27)

The base layer every gameplay system sits on. Done = the engine spawns a map's real objects with their real stats, accepts orders, steps the world at 30 ticks/s, answers spatial queries fast, and shows the same checksum every run. G1 (Lua) and G2 (space combat) build on it, leading to an AI-vs-AI space battle running headless.
